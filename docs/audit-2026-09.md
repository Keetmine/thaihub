## 1. Дыры и баги (чинить первыми)

1. Брони поездки: `saveTripBooking`/`deleteTripBooking` не проверяют
   авторство — участник может переписать/раскрыть/удалить чужую
   приватную бронь (trips/actions.ts:1055, :1143; для дел и личных
   событий `canTouchItem` есть, для броней — нет).
2. `addComment` (reviews/actions.ts:102) не зовёт `canSeeMeetup`:
   посторонний пишет комментарии под закрытой встречей сообщества.
   `saveReview` для встреч проверяет только «событие прошло».
3. Закрытое сообщество отдаёт гостю описание (левая колонка + meta
   description) — обещано «название + „закрытое“»
   (communities/[id]/page.tsx:256, :79).
4. Закрытый вид обсуждений: карточка темы без заголовка показывает
   гостю первые 90 символов ТЕКСТА (DiscussionsTab select тянет text,
   PostCard: title ?? excerpt) — обещаны «заголовки без содержимого».
5. `photoUrl` профиля пишется без валидации и уходит в голый img —
   утечка реферера/подменяемая картинка (account/actions.ts:27; то же
   lib/ownLocation.ts:56, lists/actions.ts:310). Обложки сообществ
   валидируются — перенести тот же разбор.
6. Регрессия 2026-09-09: при переводе картинок на общую FileDropzone
   потерян запрет сохранять, пока файл едет (MeetupForm,
   CreateCommunityButton; комментарии в коде обещают запрет, которого
   нет). Нужен onUploadingChange у дропзоны.
7. Лимит входа: `assertRateLimit` бросает исключение, текст в проде не
   доезжает — безликое зависание вместо «подождите» (lib/rateLimit.ts:52,
   login/actions.ts:10). Вернуть ошибку значением.
8. Три копии `requireManaged` в сообществах смотрят роль без
   `status: ACTIVE` (communities/actions.ts:89, coverActions.ts:36,
   whereActions.ts:39) — держится на том, что бан сбрасывает роль.
9. Мелочи: `toggleFavoriteEvent` без `canSeeMeetup`; админ сайта
   получает 404 на странице встречи из очереди жалоб (canSeeMeetup не
   знает isAdmin); `sendFriendRequest`/`saveOnboardingFavorites`/
   `addPerformerToList` дают 500 на несуществующий id;
   `toggleFriendNotifications` заводит mute на любой id без проверки
   дружбы; фильтр «Иду» без userId в eventList.ts:64 не ставится.

## 2. Вводит в заблуждение

- Карточка встречи для не-участника подписана «По подписке», а гейт —
  членство (EventCardLocked, MeetupsTab:131). Нужен бейдж «для
  участников».
- Нет возврата после входа: гейты редиректят на голый /login, вход
  всегда уводит в /account. Нужен ?next= (и для гостевой кнопки
  «Вступить»).
- /calendar в sitemap и без noindex, но робот получает 302 на логин.
- Canonical сериалов/артистов повторяет запрошенный адрес, а не слаг
  (dramas/[id]:135, artists/[id]:99; соседние разделы делают правильно).
  Те же rawId в хлебных крошках.
- Ошибка сети в форме создания сообщества показывается как «Укажите
  название» (CreateCommunityButton catch).

## 4. Производительность и техдолг

- Профиль: ~44 запроса и ~12 последовательных стадий на рендер; статусы,
  отметки и отзывы читаются трижды (страница/статистика/лента); review
  и trip findMany без take; до 2000 строк сериалов в RSC-payload;
  syncAchievements пишет в базу при каждом открытии профиля.
- communities/[id]: loadCommunity без React.cache — самый тяжёлый запрос
  дважды (metadata + страница). users/[id] и trips/[id] metadata — так же.
- Не кэшированы: watermark на /events, гостевая витрина /communities
  (всё соседнее — в unstable_cache 15–30 мин).
- artists/[id]: фильмография тянет полные Drama (112 КБ у топ-актёра
  ради ~6 полей) — узкий select.
- 22 FK без индекса (значимые: Comment.userId, Event.createdById/
  dramaId/locationId, Notification.actorId, PerformerSeen.performerId,
  TripPlace.locationId, TripPlaceList.listId, CommunityPost.authorId).
- trips/[id]: ~8 последовательных стадий, половина независима.
- Техдолг: RichTextEditor грузит на /api/upload со своей необработанной
  ошибкой; дубль Google-иконки (login/signup); форматирование дат мимо
  lib/dates (публично: artists/[id]:344); мёртвые i18n-ключи (список в
  выводе аудита безопасности, п.12) и мёртвый код (SectionHeading,
  mergeAgencies без кнопки и др.); файлы >1000 строк: users/[id],
  trips/[id], artists/[id], trips/actions, dramas/[id].
