# Полный аудит проекта — август 2026

Снимок состояния на 2026-08-22 по пяти направлениям: админка, публичный
фронт, тексты, юридика, техническое качество. Это рабочий документ под
большой цикл «доработка всего, что есть»; по мере закрытия пунктов
переносить их в roadmap.md как задачи и вычёркивать здесь.

## Общий вывод

Код написан аккуратно (типизация без any, живые docs, комментарии
объясняют «почему»), «на коленке» — не про стиль, а про архитектурные
дыры: ноль кэша, ноль индексов на горячих таблицах, ноль
loading/error-состояний, картинки без оптимизации. Дизайн-система
наполовину есть (токены, 60 компонентов), но применяется
непоследовательно — отсюда «плоско». Тексты — три несмешивающихся
регистра, живой голос бренда заперт в неопубликованных вики-черновиках
и ачивках. Юридически — есть только /terms, нет политики ПДн и
cookie-согласия при включённом Вебвизоре, плюс публично доступные
PDF-билеты.

## 1. Админка

Масштаб: 85 файлов / 12,3 тыс. строк, 38 страниц, 19 пунктов меню в 4
группах (реальных экранов ~40 из-за вкладок внутри разделов).

Сквозные проблемы:

- **Нет обратной связи вообще**: 0 loading.tsx, 0 Suspense, 0
  useFormStatus при 35 submit-кнопках и force-dynamic на 35 страницах.
  Любое действие выглядит как «ничего не произошло».
- **Списки без пагинации/поиска**: events (все события + составы + даты,
  сортировка в JS — admin/events/page.tsx:29-53), wiki, feedback
  (take:100 — 101-е обращение недостижимо), finance (activeSubs без
  лимита), duplicates (вся таблица Performer и Drama в память —
  src/lib/duplicates.ts:20-29).
- **Непоследовательная UI-база**: три реализации комбобокса (общий
  EntitySelect + свои копии в DramaForm и EventForm), FormSection и
  UnsavedGuard только в 3 формах из 8, четыре способа подтверждения
  (ConfirmForm / window.confirm ×3), четыре разных PAGE_SIZE, шапка
  страницы скопирована 37 раз с гуляющим размером шрифта, строка списка
  с кнопкой удаления — 21 копия.
- **Гигантские формы**: PerformerForm 721 строка / 6 вкладок / одна
  кнопка сохранения на всё; ошибка на скрытой вкладке невидима. Раздел
  performers обслуживает 4 сущности через ?view= (2768 строк).
- **Навигация**: группа «Сервис» — свалка из 8 разнородных пунктов;
  pairings/agencies спрятаны без пунктов меню; /admin/agencies без
  page.tsx (404), мёртвый /admin/stats; мобильное меню теряет
  группировку.
- Мелкие баги: users/page.tsx:73 «Всего» показывает размер страницы;
  pairings/page.tsx:37 мёртвый Promise.resolve([]) и пустой performers
  в CreatePairingModal.

## 2. Публичный фронт

Стек: Bootstrap 5.3 (только CSS) + globals.css 2949 строк с токенами,
только тёмная тема (жёстко), акцент #ff6a3d, шрифты Geist + Space
Grotesk, 42 своих SVG-иконки. ~35 страниц.

Почему «плоско»:

- 90% контента — вертикальные стопки одинаковых .surface-строк
  (аватар + две строки текста + кнопка); событие/дорама/артист/локация
  визуально неразличимы. Ни одной bento/masonry-раскладки, крупных
  обложек, каруселей; .poster-row используется дважды на весь сайт.
- Одна анимация на проект (rise-in), 0 View Transitions, 0 stagger.
- 0 loading.tsx / Suspense / скелетонов при force-dynamic везде —
  переходы это белая пауза.
- ~20 пустых состояний «Пока пусто…» серым текстом без CTA; 404 —
  текстовая.
- Нет компонентов Card/Badge/Chip/PageHeader/EmptyState/Poster → 204
  инлайн-стиля, размеры заголовков гуляют (1.9–2.75rem), паттерн
  eyebrow+h1 скопирован в 17 страницах.
- Картинки: 0 next/image, 39 сырых img (lazy/decoding есть), нет
  blur-up/srcset; обложки релизов на главной выводятся аватаром 3rem.
- Мобильная: бургер-dropdown вместо drawer (не закрывается по
  Esc/клику мимо), нет нижнего таб-бара при PWA standalone, пункты
  меню задублированы в layout, календарь 7 колонок на 375px.
- Рассинхрон: themeColor/manifest #160a1c (старая фиолетовая тема) при
  фактическом фоне #0a0a0c.
- Лендинг — каноническая SaaS-лесенка без единого скриншота продукта.

## 3. Тексты и позиционирование

- Определение проекта повторяется 6 раз в 4 разных редакциях одной
  SEO-формулы (layout, about, help, футер, manifest, бот) — голоса
  бренда нет. Терминология плавает: фанмит/фан-встреча/фан-мит-ап,
  актёр/исполнитель/артист, сериал/дорама, афиша/расписание.
- Три регистра: SEO-машина (лендинг, meta), нейтрально-утилитарный
  (интерфейс), «свой человек» (ачивки, вики-черновики, «Кого вы
  любите?»). Третий — и есть голос бренда, но он почти не виден.
- /about не имеет собственного текста (рендерит лендинг); самая внятная
  страница «о проекте» — /terms.
- 4 готовые вики-статьи (билеты, авиабилеты, виза, фанмит) лежат
  неопубликованными в scripts/seed-wiki-drafts.ts, а /wiki показывает
  «Статьи скоро появятся». ЗАМЕЧАНИЕ: roadmap утверждает, что статьи
  опубликованы владельцем — сверить фактическое состояние БД.
- Противоречие лендинга и пейволла: «01 Зарегистрируйтесь — доступ ко
  всей афише», но /events для новичка — пейволл. CTA «К афише» ведёт
  на /, а не на афишу.
- Подписка продаётся списком запертых разделов, ни одной причины
  платить с точки зрения пользователя.
- Метаданные-дыры: /events, /day/[date], /users/[id],
  /artist-lists/[id] без generateMetadata.
- README.md — «# ThaiHub», устаревшее описание и имя БД.
- Аудитория женская, тексты гендерно-нейтральные с канцелярским
  «передал(а)» — решить сознательно, как обращаемся.

## 4. Юридика (факты; выводы — за владельцем/юристом)

Что есть: /terms (внятный), scrypt-пароли, httpOnly-сессии,
soft-delete аккаунта (только админом), sourceUrl у локаций и
блок «Источники» у артистов/локаций, честные UA у части импортёров.

Дыры (полный список — в отчёте, ключевое):

1. **Нет политики конфиденциальности** и вообще какого-либо документа
   об обработке ПДн, при этом собираются email, ДР, пол, страна,
   telegramId и поведенческие данные.
2. **Нет cookie-баннера/согласия**, при этом Яндекс.Метрика запускается
   безусловно с **Вебвизором** (запись сессий) и Sentry с Session
   Replay при ошибках — для всех, включая гостей.
3. **/terms утверждает «Данные не передаются третьим лицам»** — а
   фактически уходят в Метрику, Sentry (за пределами РФ), Telegram,
   Google. Прямое противоречие, править текст.
4. **PDF-билеты и брони отелей публично доступны**: /uploads/* раздаёт
   Caddy без проверки сессии, защита — только неугадываемость UUID.
   Файлы броней не удаляются никогда.
5. Нет чекбокса согласия с условиями при регистрации; нет ссылки на
   /terms с экрана оплаты.
6. Нет самоудаления аккаунта и экспорта своих данных; нет процедуры
   для правообладателей (только абзац в terms) и для актёров-субъектов
   ПД (храним ДР, рост/вес, birth name).
7. Нет реквизитов оператора/владельца нигде на сайте.
8. Атрибуция неполная: у дорам нет блока «Источники» (при контенте с
   blscene/MDL), у событий (TTM) и агентств (Wikipedia) — тоже.
9. /friends показывает чужой email в поиске пользователей любому
   залогиненному; поиск по email — contains.
10. Рассылка /admin/broadcast игнорирует пользовательские тумблеры
    уведомлений; жаловаться нельзя на комментарии и отзывы.
11. Часть импортёров маскируется под браузер (mydramalist, ficbook,
    youtubeMusic) и обходит Cloudflare-челленджи — зона риска ToS.
12. Возрастной рейтинг: тематика BL, теги NC-17 — ничем не гейтится и
    нигде не заявлен.

## 5. Техническое качество и производительность

Топ проблем по влиянию (полные таблицы — в отчётах агентов):

1. **Нет стриминга**: 0 Suspense/loading.tsx, водопады по 6-9
   последовательных await (artists/[id] — 8), React.cache не
   используется, generateMetadata дублирует запросы страницы.
2. **48 из 67 моделей без @@index**; Prisma не индексирует FK в
   Postgres. EventPerformer по performerId — seq scan на каждом
   профиле артиста; 79 contains/insensitive без trigram-индексов.
   Самый дешёвый и самый выгодный фикс.
3. **Кэша нет вообще**: 60 страниц force-dynamic, 0 unstable_cache;
   253 вызова revalidatePath — no-op-церемония (11 из них — на
   переименованный /performers). /admin — 25 запросов на заход,
   sitemap.xml пересчитывается на каждый визит робота.
4. **getCurrentUser() без React.cache** — 99 вызовов, 2-3 запроса к БД
   на любой странице до полезной работы. Тривиальный фикс.
5. **Картинки**: 845 МБ / 20,5 тыс. файлов отдаются полноразмерно в
   64px-карточки; next.config.ts без images/headers; sw.js кэширует
   uploads cache-first навсегда без вытеснения; ежедневный бэкап
   tar'ит все 845 МБ ×15 копий.
6. **Нет error.tsx/global-error.tsx**, 96 throw new Error("русский
   текст") в actions — в проде текст до пользователя не доходит.
   (Roadmap-пункт про { ok, error } закрыт лишь частично.)
7. **N+1**: /trips — 2 COUNT на каждую поездку (платный раздел!);
   uniqueCatalogSlug в prisma.$extends — до 50 findFirst на каждый
   create в импортёрах (вероятная причина медленных импортов);
   reassignJoinRows — построчные UPDATE в транзакции слияния.
8. **chromium.launch() в публичном server action**
   (lists/actions.ts:139,199 — короткие Google Maps-ссылки): 2-5 сек и
   ~250 МБ RAM на клик пользователя, параллельные клики — риск OOM.
   Плюс mdlClient headless:false на сервере не запустится.
9. **Тесты**: 12 e2e, ни одного про деньги (вебхук Stars, премиум-гейты,
   промокоды не покрыты), юнит-тестов нет, e2e не гоняются в CI.
10. **Списки без пагинации в проде**: /admin/events, /locations/map
    (полные строки без select), /admin/duplicates, календарь месяца с
    performer:true — рецепт фикса уже отработан на /locations и
    /artists.

Что сделано хорошо и что не сломать: RSC-дисциплина (ни одной
клиентской page.tsx), безопасные загрузки (MIME-allowlist, WebP,
запрет SVG), proxy без БД, пагинация /events как образец, зрелая
инфраструктура (Caddy, бэкапы, healthcheck, Sentry, rate-limit).
