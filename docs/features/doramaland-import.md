# dorama.land: русские названия и описания

Источник русских текстов каталога (Ж4б, решение владельца): русская
версия сайта показывает русские название и сюжет сериала, а другого
источника русского у нас нет. Сайт отдаётся обычным GET без защиты и
размечен микроданными schema.org — парсер
(`src/lib/doramaland.ts`, `parseDoramaLandPage`) держится за
itemprop-атрибуты и подписи полей, не за вёрстку.

## Что берём

- **Русское название** — с карточки, без служебного хвоста
  («Узел сериал с 2026 г.» → «Узел»). Хвосты и приставки:
  «(веб-)дорама», «сериал/фильм/лакорн …»; «N сезон» — часть названия.
  Ловушка, стоившая часа: `\b` в JS-регулярках знает только латиницу,
  после кириллического слова «границы нет» — срез молча не срабатывал.
- **Русское описание** — абзацы `itemprop="description"`, склейка через
  пустую строку.
- **ВСЕ варианты названий** (владелец: «абсолютно все, на всех
  языках») — русское, украинское, английское, «Оригинальное» —
  доливаются в `alsoKnownAs` (слияние без повторов, `mergeTitleVariants`;
  `titleRu` в alsoKnownAs сознательно НЕ дублируется — поиск читает его
  отдельным полем в `dramaTitleWhere`). После этого сериал находим
  поиском и по «Узел», и по «Вузол».

Остальные их поля (жанры, серии, страна) не пишем — источник этих
данных у нас MDL.

## Куда пишем

`Drama.titleRu`, `Drama.synopsisRu`, `Drama.doramalandUrl` (@unique).
Показ — `src/lib/dramaLocale.ts`: `dramaTitleForLocale` /
`dramaSynopsisForLocale`, подстановка с запасным вариантом (нет
русского — английское, как раньше). Подключено: страница сериала
(заголовок, мета, синопсис; английское название уходит в строку
альтернативных), каталог `/dramas` (включая группировку по буквам —
«Узел» встаёт под «У»), плитки поиска, живые подсказки шапки, блоки
главной («Смотрю сейчас», «Серия сегодня»).

«Нет ру перевода» в админке (фильтр сериалов, флаг `noRu`) — это
просто `titleRu IS NULL`: отдельной пометки не нужно, не найденные на
dorama.land так и остаются без перевода.

`doramalandUrl` виден и читателю: на странице сериала он выводится в
блоке «Источники» рядом с MyDramaList и blscene (подпись — hostname,
то есть «dorama.land»; строка есть только у сериалов с переводом).
Это выполнение обещания из /terms — источники указаны на страницах
записей — для русских текстов.

## Массовый прогон

`scripts/doramaland-sync.ts` — тонкая обёртка над
`src/lib/doramalandSync.ts` (`runDoramaLandFullSync`; там же живёт и
ежедневная задача, см. ниже). Один обход их каталога кормит оба
прогона. Страницы сериалов собираются из sitemap-ов (странички серий
`…-N-seriya`, в том числе с хвостом `…-8-seriya-2025`, теги и
служебные страницы с подчёркиванием вроде `privacy_policy`
отсеиваются), разобранное кэшируется в
`private-uploads/doramaland-cache.json` — прерванный прогон
продолжается, а не начинается заново. Кэш общий с ежедневной задачей.

- **Прогон 1 (всегда):** их странице ищется наша запись — по
  английскому/оригинальному названию + год (±1) + однозначность
  (двое кандидатов = пропуск); тайское «Оригинальное» сверяется с
  `nativeTitle`. Совпавшей пишутся русские поля; пустые не
  перезаписываются (`--overwrite` — перезаписываются).
- **Прогон 2 (`--import-missing`):** их сериалы без нашей записи, и
  только Таиланд ИЛИ яой/BL в жанрах (фильтр владельца; их
  «Яой / BL / Сёнэн-ай» — одно значение со слэшами, ищем подстрокой).
  Сериал сперва ищется на MDL (точное название + год, однозначно) и
  заводится обычным MDL-импортом со всем фаршем; русские поля
  доливаются следом. Не нашёлся на MDL — в отчёт: голая запись без
  постера и данных хуже, чем никакой.

```
docker compose exec app npx tsx scripts/doramaland-sync.ts            # черновой
docker compose exec app npx tsx scripts/doramaland-sync.ts --apply
docker compose exec app npx tsx scripts/doramaland-sync.ts --apply --import-missing
```

## Ежедневная задача «dorama.land: русские переводы»

Задача расписания `doramaland-sync` (`JOB_DEFINITIONS`, раз в сутки,
вкладка «dorama.land» на `/admin/schedule`; прогоны — в журнале
импортов, kind `doramaland-sync`, с лентой «Спарсенное»: дописанные
переводы как `updated`, заведённые сериалы как `created`). Просьба
владельца: раз в день смотреть, «есть ли у них что-то новое, чего у
нас нет, либо что-то новое с переводом, что у нас уже есть».
Реализация — `runDoramaLandDaily` в `src/lib/doramalandSync.ts`;
руками то же самое: `npx tsx scripts/doramaland-sync.ts --daily
[--apply] [--limit N]` (без `--apply` — сухой прогон, `--limit`
режет и страницы, и MDL-поиски).

**Что считается новым.** `lastmod` в их sitemap для этого бесполезен:
у страниц сериалов стоит время генерации самой карты (одна и та же
секунда на все ~1800 записей карты; настоящие даты — только у страниц
серий). Поэтому «незнакомая» страница — та, которой нет ни в кэше
разобранных страниц, ни в `Drama.doramalandUrl`. Sitemap-ы читаются
каждый прогон целиком (это ~27 файлов, не страницы сериалов), а
страницы — только незнакомые, не больше 300 за прогон
(`DAILY_MAX_PAGES`); остаток «дочитывается» в следующие дни — так
первый прогон без кэша (или после потери кэша) не обходит весь их
каталог за одну ночь. Пауза между запросами — 350 мс, как у скрипта.

**Что делается с прочитанным** (в таком порядке):

1. **Наши сериалы без `titleRu`** сводятся с кэшем в памяти, без
   запросов: по `title`, вариантам из `alsoKnownAs` и `nativeTitle`
   против латинских вариантов и тайского «Оригинального» с их страниц,
   год ±1, ровно одна страница-кандидат — и обратная проверка теми же
   правилами, что у прогона 1 (`findOurDramaForPage`: однозначно и с
   нашей стороны). Так перевод находится и для сериала, заведённого у
   нас позже, чем их страница попала в кэш (например, вахтой новинок
   MDL). Совпало — пишутся русские поля и варианты названий, как в
   прогоне 1; заполненное не перезаписывается.
2. **Прочитанные за прогон страницы** прогоняются через сведение
   прогона 1. Совпало с сериалом без перевода — перевод дописан;
   совпало с сериалом, у которого перевод уже есть (с другой их
   страницы), — адрес запоминается как «решённый» и больше не
   смотрится.
3. **Их сериалы без нашей записи** — фильтр прогона 2 (Таиланд или
   яой/BL): сперва новые страницы этого прогона, потом хвост из кэша.
   Сериал ищется на MDL (точное название + год, однозначно) и
   заводится обычным MDL-импортом с пометкой «обновлять по
   расписанию» и урезанным кастом (главные роли + знакомый второй
   план, из той же страницы — как у вахты новинок MDL), затем
   получают русские поля. Не больше 40 MDL-поисков за прогон
   (`DAILY_MAX_MDL_LOOKUPS`), пауза 1,5 с — хвост из тысяч тайских
   сериалов, которых у нас нет, расходится по дням, новые страницы
   идут первыми. Не нашёлся на MDL — в сводку, запись не создаётся;
   адрес запоминается и повторно ищется не раньше чем через 30 дней
   (страница на MDL могла появиться позже перевода).

**Что пропускается.** Сериалы с заполненным `titleRu` не трогаются
вовсе, и на их страницы dorama.land никто не ходит (их адреса заняты в
`doramalandUrl`, поэтому не считаются незнакомыми). Страницы не нашего
профиля (не Таиланд и без яой/BL), не совпавшие ни с чем, просто лежат
в кэше — вернутся в шаг 1, если такой сериал появится у нас.

Состояние между прогонами — `private-uploads/doramaland-sync-state.json`
(«решённые» адреса и даты неудачных MDL-поисков); при сухом прогоне
оно не пишется, кэш страниц пополняется. Остановка кнопкой в
`/admin/imports` — через `checkImportCancelled` между страницами и
тайтлами, как у остальных задач. Сводка прогона: страниц в sitemap /
новых / прочитано (и сколько осталось), переводов дописано, заведено с
MDL (с названиями), не нашлись на MDL (с названиями), ждут MDL-поиска,
ошибок.

## Правка русских полей руками

Форма сериала в админке — секция «Русские название и описание»:
`titleRu`, `synopsisRu` и `doramalandUrl` (со ссылкой на источник).
Читаются в `getDramaDetailFields`, то есть и при создании, и при
правке; три поля перечислены в списке для истории правок, иначе правка
русского названия не оставляла бы следа в аудите. В списке
`/admin/dramas` русское название идёт подстрокой — сразу видно, у кого
перевода нет.

Смысл в том, что тексты набивает парсер: ошибся — взял чужое описание,
опечатался в названии — и поправить это должно быть можно в интерфейсе,
а не в базе.

`doramalandUrl` уникален (одна их страница — один наш сериал). Вставка
занятой ссылки отбивается понятным сообщением; без проверки это падало
бы сырым P2002, из которого причина не читается.

## Разовый импорт из админки

`/admin/imports` → карточка «dorama.land: русский перевод»: ссылка на
их страницу → находим сериал у нас (название + год, однозначно) →
пишем перевод. В отличие от массового прогона, заполненные русские
поля тут ПЕРЕПИСЫВАЮТСЯ: вставленная руками ссылка — осознанное
действие. Результат (или причина отказа) показывается над формой.
