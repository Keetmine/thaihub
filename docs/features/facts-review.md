# Факты на проверку (/admin/facts)

Очередь фактов об артистах с внешних источников — просьба владельца
2026-09-26: «когда парсятся дополнительные факты — открыть в админке,
чьи они: поле оригинал, что после, и перевод, три колонки, как на
гитхабе с +; и чтобы я могла руками править и оригинал, и перевод».

Раздел **только для админа** (`requireAdmin`), менеджеру каталога не
виден: это правка текстов, которые уходят на витрину на двух языках.

## Почему очередь

Раньше импорт группы с фандома писал факты в карточку сам — и только
если их не было, и только по-английски. У артиста с фактами пришедшее
терялось, а у артиста без них на русской странице висел английский
текст. Теперь импортёры кладут факты в `FactsReview`, в карточку они
попадают только после решения владельца.

## Жизнь записи

| Статус | Что значит |
|---|---|
| `PENDING` | импортёр положил пришедшее (`incoming`), модель ещё не обрабатывала |
| `READY` | есть предложение: `proposedEn` / `proposedRu` и снимок наших фактов (`baseEn` / `baseRu`) |
| `APPLIED` | владелец применила — списки в карточке |
| `REJECTED` | отклонено |

**Постановка** — `enqueueFacts(performerId, source, facts, url)` в
`src/lib/factsReview.ts`: факты, которые у нас уже есть дословно, не
ставятся; по артисту и источнику держится одна открытая запись —
повторный импорт дописывает в неё, без повторов, и сбрасывает
устаревшее предложение в PENDING.

**Обработка** — пока руками, через подагента на дешёвой модели:

```bash
npx tsx -r dotenv/config scripts/facts-review-export.ts   # PENDING → tmp/facts-review/batches
# подагент по scripts/prompts/facts-review.md → tmp/facts-review/out
npx tsx -r dotenv/config scripts/facts-review-import.ts   # → READY
```

Главное правило промпта: **наши факты переносятся дословно**, к ним в
конец добавляется только новое — пересказанное своими словами и
переведённое. Иначе сравнение показало бы каждую нашу строку как
изменённую. Импорт это проверяет и отказывает, если наши строки
переписаны. Чтобы обработка шла сама по расписанию, нужен ключ API —
без него сайт модель вызвать не может.

**Решение** — `/admin/facts/[id]`: три колонки — оригинал (наши
факты), после (английский итог) и перевод (русский итог); в двух
последних новые строки отмечены «+» зелёным, пропавшие «−» красным
(`diffFacts`, сверка множеств без учёта регистра и конечной точки).
Ниже — поля ручной правки обоих списков, по факту на строку; «строка N
перевода — перевод строки N оригинала», длины обязаны совпадать.
Сохранение переводит запись в READY, так что применить можно и
собранное целиком руками, без модели.

**Применение** (`applyFactsReview`) пишет `trivia` и
`translations.ru.trivia`, а прежние списки — в `TextRewrite` (если
отметки ещё не было), так что откат работает как у остальных текстов.

## Источники

- **tpop.fandom.com** — оба пути импорта: через группу
  (`tpopFandomImport.ts`, раздел «Trivia» статьи участника) и со
  страницы артиста или агентства (`tpopAgencyImport.ts`). Источник
  `tpop-fandom`. Второй путь раньше ПЕРЕЗАПИСЫВАЛ факты целиком: у
  Onglee владелец завела свои, и импорт со страницы вики заменил их
  чужими без следа (жалоба 2026-09-26).
- **kprofiles.com** — разовый импорт 2026-09-26 шёл своим конвейером
  (см. [kprofiles-import.md](kprofiles-import.md)), в очередь не попадал.

**Счётчик в меню** — у «Факты на проверку» (ждут решения + ждут
обработки) и у «Дубли» (группы без «не сливать»). Дубли считаются
проходом по всему каталогу, поэтому число кешируется на 15 минут
(`pendingDuplicateCount`); слияние и «не сливать» сбрасывают кеш.
