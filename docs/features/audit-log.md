# История правок каталога

Кто, когда и что поменял в каталоге. До появления роли менеджера правки
были анонимны: непонятно, кто затёр поле и что там стояло раньше.

## Что пишется

Модель `AuditLog` (`prisma/schema.prisma`): автор (`userId` + `userLabel`
— подпись на момент правки, чтобы история пережила удаление аккаунта),
действие (`CREATE` / `UPDATE` / `DELETE` / `MERGE` / `BULK`), тип и id
записи, её название на момент правки, список изменившихся полей и
свободная приписка `note`.

Пишет `src/lib/audit.ts`:

- `logAudit({ action, entityType, entityId, entityLabel, changes, note })`
  — никогда не роняет вызывающий экшен: сохранённая запись важнее её
  журнала. Вне HTTP-контекста (скрипты, импорты) автор пишется как
  «система».
- `diffRecords(before, after, fields)` — сравнивает снимки записи по
  строковому представлению: из формы всё приходит строками, а из БД —
  числами и датами, и `"2023"` vs `2023` иначе попадало бы в историю при
  каждом сохранении. Пустой список изменений не пишется вовсе.

Подключено к server actions исполнителей, сериалов, событий, агентств,
локаций, новелл, альбомов/песен (`musicActions.ts`), к слияниям дублей
(`src/lib/duplicates.ts`, действие `MERGE`) и к массовым действиям
(`bulkActions.ts`, действие `BULK`).

Импорты (tpop.fandom, TMDB, MDL, blscene) в журнал не пишут — у них свой
`ImportRun` с прогрессом и итогами, дублировать тысячи строк
бессмысленно.

## Где смотреть

- **Карточка записи** — блок «История правок» внизу формы
  (`AuditTrail`, `hideWhenEmpty` — у записей старше журнала истории
  нет, блок не рисуется). У исполнителя это отдельная вкладка формы.
- **`/admin/history`** — общая лента с фильтрами по типу записи и по
  автору, пагинация. Доступна и менеджеру каталога. Строка кликабельна
  и ведёт на карточку; у удалённых записей ссылки нет.

## Массовые действия

`BulkList` (`src/components/admin/BulkList.tsx`) добавляет к списку
чекбоксы и липкую панель действий. Действия приходят из серверного
компонента, поэтому это данные плюс server actions — текст
подтверждения задаётся шаблоном `confirmTemplate` с `{n}`, а не
функцией.

Сейчас подключено:

- исполнители: удалить выбранных, сменить агентство (заменяет текущие
  привязки — разбор импорта, где артисты осели не в том лейбле);
- агентства: удалить выбранные;
- сериалы: удалить, сменить агентство, проставить статус.

Каждое действие пишет в историю одну строку `BULK` с перечислением
первых пяти названий и «ещё N».
