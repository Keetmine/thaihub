# tpop.fandom: импорт агентства целиком (и одиночных артистов)

`/admin/imports` → форма «tpop.fandom: импорт агентства» (URL страницы
вида https://tpop.fandom.com/wiki/RISER_MUSIC) или CLI:
`npx tsx scripts/import-tpop-agency.ts <url>`. Рядом — форма
одиночного импорта артиста/группы (`importTpopArtist`, CLI
`scripts/import-tpop-artist.ts <url>`, kind `tpop-artist`): тот же
полный пайплайн для одной страницы, агентство берётся из поля Agency
самой страницы (текущее — parseCurrentAgencyName), тип группа/соло
определяется по инфобоксу. Доступ — через
официальный MediaWiki `api.php` (см. [tpop-band-import.md]
(tpop-band-import.md)); контент CC BY-SA, на странице исполнителя
внизу выводится блок «Источники» (сноски References + ссылка на
страницу-источник с пометкой лицензии).

## Что делает (src/lib/tpopAgencyImport.ts)

1. **Агентство**: создаёт/находит по имени (ci), лого из инфобокса —
   только если поле пустое.
2. **Артисты** из секций Groups / Duos («Duo» у DMD Music) / Soloists /
   Former artists (опция `skipFormer` / CLI `--skip-former` пропускает
   бывших целиком; `onlyGroups` / CLI `--only-groups "A,B"` импортирует
   из групп/дуэтов только перечисленные, солистов не трогая): группы (в инфобоксе есть участники — «Current», у
   распавшихся фолбэк на «Former», иначе SIZZY-подобные распавшиеся
   группы выглядели бы как соло; участники-«красные ссылки» без своей
   страницы — `span.new` у рок-групп Genie вроде Bodyslam — тоже
   считаются составом, но записей под них больше не заводится) идут через
   `importTpopBand`,
   солисты матчатся по name/musicAlias/realName (ci) + нормализованный
   фолбэк по realName без дефисов/пробелов («Opas-iamkajorn» ↔
   «Opasiamkajorn»); мимо — создаётся новый. Former artists
   импортируются, но текущим агентством не привязываются.

   **Одного ника мало** (правка владельца 2026-09-10): совпадение
   считается настоящим, только если подтверждено НЕ ником — настоящим
   именем или датой рождения. Раньше здесь стоял `findFirst` по имени,
   и из пяти «Gun»-ов выигрывал первый попавшийся. Не подтвердилось —
   заводится новый (дубль виден в «Дублях» и сливается, ложная привязка
   не видна никак). Подтверждать нечем (на вики нет ни настоящего
   имени, ни даты): единственный тёзка считается им — иначе каждый
   прогон плодил бы новую запись, — а из нескольких артист пропускается
   с записью в журнал прогона.

   Участники-«красные ссылки» без своей страницы записей больше НЕ
   получают: их имена уходят в описание группы строкой
   `Members: A, B, C.` — см. [tpop-band-import.md](tpop-band-import.md).
   Лейбл группы («Label(s)») идёт через `parseCurrentAgencyName`, как и
   агентство участника, — сырая история («Bridge Management
   (2026-present), Gene Lab (2018-present)») больше не превращается в
   мусорное агентство с датами в имени.
3. **Расширенный профиль** (`src/lib/tpopArtistExtras.ts`, поля на
   Performer): occupation[], instruments[], soloDebut, height, weight,
   mvAppearances[] (текстом), trivia[], awards (Json-таблица
   year/award/category/nominee/result), references (Json [{label,url}]),
   sourceUrl. Пустые спарсенные значения не затирают ручные.
4. **Дискография**: альбомы/песни через `fetchTpopDiscography`; со
   страниц альбомов/песен берётся обложка и первая «площадочная»
   внешняя ссылка (YouTube/Spotify/Apple, официальный
   `prop=externallinks`) → Album.url / Song.url.
5. **Концерты** (прошедшие тоже): строки секций Concerts/Fanmeetings
   читаются вместе с h3-подсекциями (Tours/Solo/участия —
   `sectionElements`, обход до следующего h2; `contentAfterHeading`
   отдаёт только первый элемент и подсекции не видел). Сверка с афишей
   нормализованным сравнением названий; совпадение — артист
   привязывается. Новые собираются из двух источников:
   - **вики-страница концерта** (ссылка из строки, чей текст совпадает
     с названием — иначе это ссылка «(with Gemini)» на артиста):
     инфобокс по data-source — артисты (включая гостей), даты
     (диапазоны «August 26-27, 2023» и кросс-месячные разворачиваются
     по дням), площадка, постер;
   - **thaiticketmajor**: страницы прошедших концертов живы — URL
     угадывается по слагу названия (`guessTtmEvent`,
     /concert/<slug>.html и /performance/), фолбэк — поиск по сайту
     (отдаёт только текущие продажи).
   Если TTM нашёлся — событие создаётся с его временем/ценой/
   постером/препродажей; иначе — по вики-данным с датами без времени
   (hasTime=false). Ко всем событиям привязываются артисты
   концерта, ОДНОЗНАЧНО найденные в каталоге по имени/алиасу
   (`linkEventArtists`) — и хозяева, и приглашённые гости, из обоих
   источников. Тёзки разводятся только контекстом: человек из состава
   группы, уже привязанной к событию, — это он («Tui» из LYKN важнее
   случайного актёра Tui). Не развелись — привязки нет, имя уходит в
   журнал прогона (правка владельца 2026-09-10; раньше при пяти
   «Gun»-ах цеплялся случайный). Дедуп в
   рамках прогона (один концерт в списках нескольких артистов). Совсем
   без дат — `concertsNotFound` в summary.

## Форматы «Artists» на TTM

`scrapeTtmEvent` понимает все встреченные формы строки состава: метки
«Artist(s)» / «Performers» / «Line Up»; имена «Full Name (Nick)» и
обратную «(Nick) Full Name»; разделители `<br>` и « / »; голые строки
до `<div>`-блоков и внутри них; формат «ГРУППА — (Участник, Участник,
…)» разворачивается в отдельных артистов (riser-concert-the-first-rise).

## Прогресс импорта в админке

Запуск из формы — fire-and-forget: экшен создаёт `ImportRun`
(RUNNING) и сразу возвращается, импорт идёт в фоне, а onProgress
пишется в `run.summary` (троттлинг 2с). Страница показывает спиннер с
текущим шагом, кнопка блокируется, `RunningImportsWatcher` (клиент)
рефрешит страницу каждые 4с, пока есть RUNNING-запуск; упавший импорт
получает статус FAILED с последним шагом и ошибкой в summary.

Прогон можно остановить кнопкой: в длинных циклах (группы, солисты,
бывшие артисты, альбомы, песни, концерты) стоит
`checkImportCancelled(ctx.runId)`, поэтому импорт выходит после
текущего элемента, а всё уже записанное остаётся в каталоге — см.
[admin-panel.md](admin-panel.md), раздел «Импорты». Этот запуск ведёт
свою запись `ImportRun` сам, мимо `logImportRun`, и остановка приходит
к нему обычной ошибкой — в журнале она видна последним шагом и
пометкой «Остановлено вручную» в summary.

## Журнал «последнее спарсенное»

Каждый созданный/обновлённый объект пишется в `ImportedItem`
(runId → ImportRun, entityType, entityId, action, label) — лента на
`/admin/imports` со ссылками на админ-редактирование. Сюда пишут
автоматические импорты; ручное добавление не логируется.

## Вывод на странице исполнителя

Инфо-строки (занятия, инструменты, сольный дебют, рост/вес) + секции
«Появления в клипах», «Награды и номинации» (таблица, Won —
зелёным), «Факты», «Источники» — внизу страницы.

## Слияние дублей

`mergePerformers` переносит и музыку (Album c разрешением конфликта
по (performerId,title) — песни переезжают в одноимённый альбом
выжившего), Song и строки кастомных списков — без этого каскад
удаления проигравшего терял бы их молча.
