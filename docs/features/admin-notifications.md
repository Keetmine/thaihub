# Уведомления админам

Об очередях, которые ждут разбора, раньше узнавали, только зайдя в
админку. Теперь они видны в двух местах: бейджем в сайдбаре и
сообщением в Telegram.

## Бейджи в сайдбаре

`adminBadgeCounts()` (`src/lib/adminNotify.ts`) считает новые обращения,
новые жалобы, упавшие импорты и ошибки за сутки; layout админки рисует
число справа от пункта меню. Менеджеру каталога бейджи не показываются
— эти разделы ему недоступны.

## Telegram

`notifyAdmins(kind, text, { dedupKey })` шлёт сообщение всем
пользователям с `isAdmin` и привязанным `telegramId`. Никогда не
бросает: упавшее уведомление не должно ронять действие, которое его
вызвало (обращение пользователя, вебхук оплаты).

Поводы:

| kind | когда | где вызывается |
| --- | --- | --- |
| `feedback` | новое обращение | `src/app/(public)/feedbackActions.ts` |
| `report` | новая жалоба на контент | там же |
| `import` | `ImportRun` завершился как FAILED | `src/lib/importRun.ts` |
| `error` | новая серверная ошибка | `src/lib/errorLog.ts` |
| `payment` | успешная оплата подписки | `src/app/api/telegram/webhook/route.ts` |

Набор включённых поводов правится в `/admin/settings` ключом
`admin_notify_kinds` (через запятую). По умолчанию включено всё, кроме
`error`: этот поток шумный, а счётчик в сайдбаре и так виден. Пустая
строка выключает канал целиком.

Повторы гасит дедуп по `dedupKey` с окном 10 минут — одна и та же
ошибка прилетает пачками, и каждая не должна становиться сообщением.
Окно живёт в памяти процесса, то есть после рестарта первое сообщение
уйдёт снова; для этой задачи достаточно.

Почтовый канал появится, когда будут SMTP-доступы (см. roadmap).
