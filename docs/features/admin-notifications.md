# Уведомления админам

Об очередях, которые ждут разбора, раньше узнавали, только зайдя в
админку. Теперь они видны в двух местах: бейджем в сайдбаре и
сообщением в Telegram.

## Бейджи в сайдбаре

`adminBadgeCounts()` (`src/lib/adminNotify.ts`) считает новые обращения,
новые жалобы, упавшие импорты и ошибки за сутки; layout админки рисует
число справа от пункта меню. Менеджеру каталога бейджи не показываются
— эти разделы ему недоступны.

## Telegram

`notifyAdmins(kind, text, { dedupKey })` шлёт сообщение всем
пользователям с `isAdmin` и привязанным `telegramId`. Никогда не
бросает: упавшее уведомление не должно ронять действие, которое его
вызвало (обращение пользователя, вебхук оплаты).

Поводы:

| kind | когда | где вызывается |
| --- | --- | --- |
| `feedback` | новое обращение | `src/app/(public)/feedbackActions.ts` |
| `report` | новая жалоба на контент | там же |
| `import` | `ImportRun` завершился как FAILED | `src/lib/importRun.ts` |
| `error` | новая серверная ошибка | `src/lib/errorLog.ts` |
| `payment` | успешная оплата подписки | `src/app/api/telegram/webhook/route.ts` |
| `signup` | зарегистрировался новый человек | все три пути входа (см. ниже) |
| `community` | завели сообщество | `src/app/(public)/communities/actions.ts` |

Регистрация зовёт `notifyAdminsAboutSignup(user, via)` — обёртку над
`notifyAdmins`, чтобы формат сообщения не разъезжался по трём местам:
форма (`src/app/(public)/signup/actions.ts`), Google
(`src/app/api/auth/google/callback/route.ts`) и Telegram
(`src/app/api/auth/telegram/route.ts`). В тексте — способ регистрации и
то, по чему человека найти в `/admin/users`: имя, иначе почта, иначе
телеграм-ник.

Сообщение уходит **только про нового человека**: вход существующим
аккаунтом уведомления не даёт, и привязка Google к уже заведённому
email-аккаунту — тоже (это не регистрация). Промис намеренно не
дожидаются: поход в Telegram не должен ни тормозить регистрацию, ни
ронять её, если бот недоступен. `dedupKey` — id пользователя, страховка
на случай повторного выполнения обработчика.

Новое сообщество зовёт `notifyAdminsAboutCommunity(community)` — по той
же схеме, что регистрация. В тексте название, кто завёл, видимость и
прямая ссылка: закрытое сообщество не видно ни в витрине, ни в поиске,
ни в карте сайта, и это единственный способ узнать о нём вовремя.
Название экранируется под `parse_mode: "HTML"` — «Лакорны <3» иначе не
просто отвалилось бы, Telegram отклонил бы сообщение целиком.

Набор включённых поводов правится в `/admin/settings` ключом
`admin_notify_kinds` (через запятую). По умолчанию включено всё, кроме
`error`: этот поток шумный, а счётчик в сайдбаре и так виден. Пустая
строка выключает канал целиком.

Повторы гасит дедуп по `dedupKey` с окном 10 минут — одна и та же
ошибка прилетает пачками, и каждая не должна становиться сообщением.
Окно живёт в памяти процесса, то есть после рестарта первое сообщение
уйдёт снова; для этой задачи достаточно.

## Почта

Те же сообщения дублируются письмом на адрес из настройки
`admin_notify_email`, но только когда настроен SMTP (`SMTP_HOST` +
`SMTP_FROM`, см. `src/lib/mailer.ts`). Без ящика на домене канал молча
пропускается — код готов и включится, как только появятся доступы.
Все стадии SMTP-сессии ограничены 10 секундами (`connectionTimeout` /
`greetingTimeout` / `socketTimeout`): дефолтные минутные таймауты
nodemailer держали бы вызвавший код всё это время, если сервер
недоступен.
