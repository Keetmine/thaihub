# MyDramaList import

Официального публичного API у MDL нет (ключи выдают «партнёрам» по
заявке), парсим страницы. Два уровня доступа:

- **тайтлы и поиск** отдаются обычным GET'ом с браузерным User-Agent;
- **раздел `/people/`** закрыт Cloudflare-челленджем — решается только
  реальным браузером. `src/lib/mdlClient.ts` поднимает один headed
  chromium, решает челлендж навигацией и дальше ходит быстрыми
  HTTP-запросами через `context.request` (те же cookies/UA); если
  ответ снова оказался челленджем — решает заново и повторяет.

Все парсеры — чистые функции над HTML в `src/lib/mydramalist.ts`:
`parseMdlDramaPage` (JSON-LD TVSeries + блок Details + полный синопсис
из `.show-synopsis` + Related Content), `parseMdlPersonPage` (Details
человека, био из Article JSON-LD, персональные соцссылки, фильмография
из строк `tr.mdl-<id>` с ролями), `parseMdlSearchTitles` /
`parseMdlSearchPeople`.

## Импорт сериала из админки

`/admin/imports` → карточка «MyDramaList: импорт сериала»: одна ссылка
на страницу тайтла. Если сериала в каталоге ещё нет — он **создаётся**
(слаг проставляет расширение Prisma, см. `src/lib/prisma.ts`); если
есть (ищем по `mydramalistUrl`, затем по точному названию) —
дозаполняются только пустые поля. Исключение — статус: он выводится из
дат эфира и освежается всегда. Забираем оригинальное название, AKA,
описание, постер (скачивается локально в WebP), жанры, режиссёра и
сценариста, канал, число серий, даты эфира, день выхода,
длительность, возрастной рейтинг, год и оценку MDL.

**Каст приезжает вместе с сериалом.** `parseMdlDramaCast` разбирает
блок актёров на той же странице: разбор идёт «по якорям»
(`/people/<id>-<slug>` + подпись «Main Role» / «Support Role» /
«Guest Role»), а не по классам блоков — вёрстка карточек у MDL
меняется, а ссылка и подпись роли стабильны. Область поиска сужена до
блока каста, иначе в состав попали бы режиссёр и сценарист, которые на
странице тоже ссылки на `/people/`. Хвост после ссылки берётся
просмотром вперёд `(?=…)`, а не захватом: иначе матч съедал бы
следующих актёров и в списке оставался каждый второй.

Актёра ищем по ссылке на MDL, затем по имени; если в каталоге его нет
— заводим карточку-заготовку (имя + ссылка), которую потом дозаполнит
обычный импорт актёра. Существующие связи не трогаем, роли не
перезаписываем. В сводке прогона видно «каст +N (заведено актёров M)».

Это не то же самое, что кнопка на карточке сериала
(`importFromMydramalist` в `dramas/actions.ts`): та работает только с
уже существующей записью и её полем `mydramalistUrl`, а импорт из
`/admin/imports` умеет заводить сериал с нуля.

Обе кнопки ходят через общий `fetchMdlHtml` (обычный GET → chromium
headless → headed): раньше `fetchMdlDrama` дёргал голый `fetch` и
ловил от Cloudflare 403 там, где импорт актёра проходил. Если MDL
всё-таки закрылся челленджем, прогон падает с понятным сообщением в
`/admin/imports` — тогда импорт запускают с машины, которую MDL
пропускает.

## Импорт актёра из админки

`/admin/imports` → карточка «MyDramaList: импорт актёра»: ссылка на
профиль человека и (необязательно) исполнитель из каталога. Без
исполнителя карточка создаётся новая; повторный импорт того же адреса
находит её по `mydramalistUrl` и не плодит дублей.

Заполняются **только пустые** поля — настоящее имя, дата рождения,
биография, фото, соцссылки. Занесённое руками не переписывается: импорт
дополняет карточку, а не диктует ей содержимое.

Фильмография связывается только с сериалами, которые **уже есть** в
каталоге (по `mydramalistUrl` или названию); недостающие считаются и
показываются в сводке, но не заводятся. Это принципиально: массовый
обход TMDB удалили как раз за то, что он тащил в каталог сотни чужих
сериалов и персон — см. [tmdb-import.md](tmdb-import.md).

Длинные шаги (соцссылки, фильмография) проверяют
`checkImportCancelled`, так что импорт можно остановить кнопкой на
`/admin/imports`: он выйдет после текущей строки, а карточка останется
такой, какой успела получиться, — повторный импорт того же адреса её
дозаполнит (см. [admin-panel.md](admin-panel.md), раздел «Импорты»).

`fetchMdlPerson` сначала пробует обычный fetch и только при
Cloudflare-челлендже поднимает chromium (headless, затем headed) —
порядок как у импорта с Фикбука. С прод-сервера страницы отдаются
обычным GET'ом; из некоторых сетей MDL закрыт полностью, тогда импорт
запускают с машины, у которой доступ есть.

## Массовые прогоны

**`scripts/mdl-sync-dramas.ts`** — по всем сериалам каталога. Страница
находится по сохранённому `mydramalistUrl` или поиском: для латинских
названий — точное совпадение нормализованного названия (при
неоднозначности — ближайший год), для тайских — кандидаты
верифицируются их страницами (Native Title / AKA должны содержать наше
название). Пишет: nativeTitle, alsoKnownAs, синопсис (перезаписывается —
MDL полнее TMDB), director, screenwriter, genres[], tags[], episodes,
airedFrom/To/On, duration, contentRating, mdlScore, network, статус (по
датам эфира), постер (если не было). Блок Related Content разрешается в
`DramaRelation` (по mdl-id или названию, только между сериалами, уже
существующими в каталоге) в конце прохода. Резюм — по `mdlSyncedAt`
(«не найденные» тоже помечаются, `--force` для повторного полного
прохода). Не найденные — в основном не-тайский мусор TMDB-импортов
(корейские/китайские/американские тайтлы).

**`scripts/mdl-sync-performers.ts`** — ТОЛЬКО по актёрам с агентствами
(type SOLO). Человек ищется поиском по `имя + realName`; кандидат
принимается, если его фильмография пересекается с нашими сериалами
этого актёра или полное имя совпадает с realName. Пишет: alsoKnownAs,
nationality, gender (всегда), realName/birthDate/bio (только если
пусто; Native name сознательно не берём), недостающие соцссылки
(платформа распознаётся по URL, дубликаты платформ не создаются), и
сверяет фильмографию: недостающие `PerformerDrama` создаются, у всех
матчей проставляется роль (имя персонажа) с MDL.

**`scripts/cleanup-foreign-performers.ts`** — чистка каталога от мусора
TMDB-импортов: исполнители БЕЗ агентства с не-латинскими именами
(тайская/CJK/корейская письменность) или местом рождения из явного
списка не-тайских стран. Определять «американца» по имени ненадёжно (у
тайцев западные ники) — сигналом служит только place of birth из TMDB.
Никогда не удаляет связанных с агентством/событиями/группами/
пейрингами/избранным. Без `--apply` — dry-run. Прогон 2026-08-16
удалил 10 504 записи (осталось ~8.1 тыс.).

## Точечная кнопка в админке

«Подтянуть с MyDramaList» на `/admin/dramas/[id]/edit` — то же самое
для одного сериала по ссылке из поля mydramalistUrl: заполняет пустые
поля (описание, год, канал, постер — локально в WebP) и освежает
статус. Занятые поля не перезаписывает.

## Где это видно

Страница сериала: нативное название и AKA под заголовком, чипы жанров,
эпизоды × длительность, даты эфира (с днём недели), режиссёр,
сценарист, возрастной рейтинг, оценка MDL, полный синопсис и секция
«Связанные сериалы» (EntityMiniCard с подписью отношения — sequel,
shared universe и т.п.). Страница актёра: национальность и «Также
известен как»; роли видны в составе на странице сериала.

## Атрибуция вместо приписки в тексте

MDL добавляет в конец био/синопсиса «(Source: MyDramaList)» — парсер
вырезает её (`stripMdlSelfAttribution` в `src/lib/mydramalist.ts`), а
ссылка на источник живёт отдельно: у артиста — пунктом блока
«Источники», у сериала — кнопкой «MyDramaList ↗» под синопсисом.
Приписки на ДРУГИЕ источники (Netflix, GMMTV, Wikipedia, «Soju at
MyDramaList»…) остаются в тексте — это атрибуция чужих текстов, а не
нашего поставщика. Бэкфилл прогнан: 384 био + 612 синопсисов.
