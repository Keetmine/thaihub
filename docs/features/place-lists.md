# Мои места («Place lists»)

## Подписка

**Заводить своё — по подписке** (правка владельца 2026-09-06): создание
списка мест и создание собственного места требуют активной подписки
(`requirePremiumUser` в `lists/actions.ts`; на `/lists` кнопки заменяет
`PremiumUpsell`). Всё остальное бесплатно и работает как раньше: уже
созданные места и списки остаются у владельцев, чужие ПУБЛИЧНЫЕ списки
открыты всем — включая гостя без входа, — а места съёмок, карта и
отметка «была здесь» к подписке отношения не имеют.

Списки артистов гейтятся так же и давно (`createPerformerList`), только
там отказ — редиректом, а тут ошибкой значением: форма показывает её на
месте.

**Место — основная сущность раздела, список — необязательная
группировка.** Своё место (`Location.createdByUserId`) живёт само по
себе; `PlaceList` — подборка таких мест и каталожных локаций («где
вкусная еда», «кафе из сериалов») с той же моделью видимости, что у
поездок (PRIVATE/FRIENDS/PUBLIC).

- **`/lists`** — раздел «Мои места» (адрес не менялся). Сверху кнопка
  «+ Добавить место» (`CreateOwnPlaceButton` с готовым экшеном
  `createStandalonePlace` — место создаётся без всякой привязки) и
  список своих мест по алфавиту: миниатюра-фото (или эмодзи категории),
  название, категория и координаты, вся строка — ссылка на страницу
  локации. Ниже отдельная секция **«Списки»** с пояснением, что это
  способ сгруппировать места и поделиться подборкой, и кнопкой
  «+ Создать список». Пустые состояния: нет ни мест, ни списков — один
  `EmptyState` с призывом добавить первое место; секция мест не
  рисуется, пока своих мест нет. Секция списков остаётся видимой (даже
  пустая) — создать список больше неоткуда.
- **`/lists/[id]`** — карта пинов + строки локаций (фото, заметка
  per-место, ссылка на страницу локации). Владелец добавляет места
  асинхронным поиском (`searchLocationOptions` — тот же паттерн, что
  поиск актёров), редактирует заметки, меняет видимость, удаляет. Чужой
  список открывается по правилам видимости (404 иначе); видимые списки
  друга показываются в его профиле (`/users/[id]`).
- **Привязка к поездкам**: вкладка «Что посетить» поездки объединяет
  три источника — локации съёмок сериалов владельца (по watch-статусам),
  прикреплённые списки (`TripPlaceList`, селект «+ Прикрепить список»)
  и отдельные места (`TripPlace`, комбобокс «+ Добавить место») — все
  пины на одной карте.
- **Личное событие поездки** может ссылаться на локацию
  (`TripPersonalEvent.locationId`, `LocationPickerField` в форме) —
  карточка события показывает «📍 место» ссылкой.
- **Свои места**: кнопка «+ Добавить место» на `/lists`, «+ Создать своё
  место» на странице списка и «+ Своё место» на вкладке «Что посетить» в
  поездке — одна и та же модалка (`CreateOwnPlaceButton`, принимает либо
  `listId`, либо готовый `action`). **Список для этого не нужен**:
  раньше, чтобы сохранить одно место, приходилось сперва завести список,
  положить место туда и потом прикрепить список к поездке. Разбор формы и
  создание самой локации вынесены в `createOwnLocation(formData,
  userId)` — он живёт в `src/lib/ownLocation.ts`, обычном модуле БЕЗ
  `"use server"`: экспорт из actions-модуля делал его публичным
  HTTP-эндпоинтом, принимающим чужой userId без аутентификации. Куда
  привязать — решает вызывающий экшен:
  `createStandalonePlace` не привязывает никуда (раздел «Мои места»),
  `createOwnPlace` кладёт в список, `createTripOwnPlace` — сразу в
  поездку, `createOwnPlaceAndReturn` возвращает созданное место форме,
  которая его завела.
  Поля: название + ссылка Google Maps (короткая `maps.app.goo.gl` или
  длинная) или голые координаты «13.75, 100.50». Координаты извлекаются тем же
  `resolveMapsCoords`, что у blscene-импортёра (длинные ссылки — regex,
  короткие — headless-браузер). Ссылка здесь — пользовательский ввод,
  поэтому резолверы ходят только на хосты Google (allowlist в
  `src/lib/blscene.ts` + SSRF-защита `src/lib/urlGuard.ts`); любая
  другая ссылка просто не даёт координат. Такая локация помечается
  `Location.createdByUserId` и **не попадает** в общий каталог
  (/locations, карту, поиск, админку, комбобоксы админ-форм) — видна
  только в разделе «Мои места», списках и поездках, а
  `searchLocationOptions` находит каталог + собственные места искателя.
  Экшены, принимающие `locationId` с клиента (`addPlaceToList`,
  `addPlaceToTrip`, `toggleLocationVisit`, личные события поездки),
  проверяют его через `canUseLocation` (тот же `ownLocation.ts`):
  локация должна быть каталожной (`createdByUserId == null`) или
  своей — иначе по чужому id подтягивалось чужое приватное место.
  Отдельная вкладка «Мои места» есть и в каталоге локаций
  (`/locations`) — та же выборка `createdByUserId`, карточками.
- Пункт «Мои места» — в выпадашке профиля, в мобильном меню и в футере.

## Дополнительно

- **Редактирование**: список (название/описание — `EditListButton`) и
  собственные места (название/фото/точка — модалка ✎ в строке, только
  для `createdByUserId`-мест владельца). Фото места добавляется и при
  создании (`FileDropzone` → /api/upload).
- **Порядок**: `PlaceListItem.position` + кнопки ▲▼ (`movePlaceInList`
  переписывает позиции всего списка транзакцией).
- **«Посетила» из списка**: `VisitedButton` в каждой строке для любого
  залогиненного зрителя — та же `LocationVisit`, что на странице
  локации; питает статистику и ачивки «Паломник».
- **Публичный шаринг**: `/lists/{id}` пропускается proxy.ts без сессии —
  PUBLIC-список открывается гостю по прямой ссылке (без owner-контролов
  и кнопки «посетила»); PRIVATE — 404, FRIENDS — редирект на логин для
  гостя и обычная проверка дружбы для залогиненного.

## Списки актёров (PerformerList)

Аналог списков мест, но с актёрами («пил пиво», «видела вживую»):
`PerformerList`/`PerformerListItem`, слаг название+код, та же модель
видимости PRIVATE/FRIENDS/PUBLIC (публичные открываются по прямой
ссылке без логина — /artist-lists/[id] в proxy). Создание/список —
секция на /lists; добавление актёров — публичный async-поиск
`searchPerformersForList` (только для залогиненных, НЕ админский
экшен). Видимые спискам зрителя показываются на публичном профиле.
