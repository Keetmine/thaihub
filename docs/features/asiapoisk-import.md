# Русские названия и страны с asiapoisk.com

Второй источник русских названий после
[dorama.land](doramaland-import.md) (решение владельца 2026-09-06): он
закрывает часть каталога, до которой тот не дотянулся, и — что не менее
ценно — знает СТРАНУ, которой у трёх тысяч наших записей нет.

Разведка 2026-09-06 на живом сайте: у них ~27 000 карточек сериалов,
пара нашлась 1626 нашим записям, из них 1170 без русского названия
(Корея 108 из 145, Тайвань 52%, Китай 55%, Япония 33%, Таиланд 69 из
454, плюс 848 у записей без страны).

## Files

- **`src/lib/asiapoisk.ts`** — чистый разбор (без сети и Prisma):
  `parseAsiapoiskPage`, карта сайта (`parseSitemapIndex`,
  `parseAsiapoiskSitemap`), ключи сведения (`matchKey`, `sitemapKeys`),
  страны (`normalizeCountry`) и проверка на кириллицу (`hasCyrillic`).
  Покрыт `tests/unit/asiapoisk.test.ts`.
- **`src/lib/asiapoiskSync.ts`** — сам прогон `runAsiapoiskSync` и
  сводка `summarizeAsiapoiskSync`.
- **`scripts/asiapoisk-sync.ts`** — разовый прогон без потолка в 200
  карточек; `--apply` пишет, без него сухой прогон с планом.
- **`src/lib/scheduledJobs.ts`** — суточная задача `asiapoisk-sync`.

## Что берём и откуда

Всё нужное лежит в `<title>` карточки:

```
Дорама Море алчности / Talay Rissaya / ทะเลริษยา (Таиланд, 2006, 2007) — Азияпоиск…
```

— русское название, английское, оригинальное, страна и годы. Читаем
именно заголовок, а не разметку страницы: она меняется чаще, а нам
нужны ровно эти четыре вещи.

**Список карточек — из карты сайта**, а не листалкой: постраничная
навигация закрыта в их `robots.txt` (и фильтры честно отдают 403), а
`sitemap.xml` разрешён. Индекс ведёт на 14 вложенных карт.

**Сведение идёт ПО КАРТЕ, не открывая страниц**: в их слаге лежит
английское название, иногда с годом (`Talay_Rissaya_2006`), и его
хватает, чтобы найти пару нашему `Drama.title`. Открываются только
совпавшие — это разница между 27 000 запросов и примерно 1400.

## Проверка совпадения — обязательная

Каждое совпадение сверяется по стране и году из заголовка
(`rejectReason`):

- **страна** сверяется, только когда она есть у обоих: у трёх тысяч
  наших записей её нет — как раз их мы и хотим заполнить;
- **год**: наш должен быть среди их годов (у многосезонных их два);
- **если проверить нечем** (у нас нет ни страны, ни года) — пропускаем.
  Угадывать чужой перевод нельзя: одинаковых названий у ремейков полно.

Без этой проверки нашему тайскому «Why R U» досталось бы название
корейского ремейка — поймано на разведке. В сухом прогоне на живых
данных проверка отсеяла 4 совпадения из 12.

## Что пишем

Только ПУСТОЕ: `titleRu`, если его нет, и `country`, если её нет.
Проставленное руками или другим источником не трогается. «Русское»
название, оказавшееся продублированной латиницей, переводом не
считается и не записывается.

Разобранный адрес запоминается в `Drama.asiapoiskUrl` (уникален: одна
их карточка — один наш сериал), даже когда дописать было нечего: второй
раз на эту страницу никто не пойдёт, и прерванный прогон продолжается с
места обрыва.

## Прогон

Сайт просит паузу 2 секунды между запросами (`Crawl-delay` в
robots.txt), и мы её держим: суточная задача читает до 200 карточек,
остаток добирает назавтра; полный разовый прогон идёт около сорока
минут.

```
npx tsx scripts/asiapoisk-sync.ts             # план
npx tsx scripts/asiapoisk-sync.ts --limit 50  # только первые 50
npx tsx scripts/asiapoisk-sync.ts --apply     # записать
```

На проде:

```
cd "$DEPLOY_PATH"
docker compose exec app npx tsx scripts/asiapoisk-sync.ts --apply
```

## Tests

`tests/unit/asiapoisk.test.ts` — заголовки с живых страниц: обычная
карточка, многосезонная с двумя годами, карточка без перевода (там
дубль латиницы), сущности в названии, перевод стран, ключи сведения и
отбор карточек из карты сайта. Без сети и БД:
`npx tsx tests/unit/asiapoisk.test.ts`.
